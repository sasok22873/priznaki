# AGENTS.md — правила для ИИ-помощника

Проект: «ПРИЗНАКИ БЕШЕНСТВА 24» — веб-штаб музыкальной группы.
Репозиторий: github.com/sasok22873/priznaki · Сайт: https://sasok22873.github.io/priznaki/
База: Supabase, project ref `mbbetmtxawduvcsttiis`.

## Стек (не менять без причины)
- Чистый HTML/CSS/JS. Сборки нет, npm нет, фреймворков нет.
- `index.html` (~175 КБ, 2 встроенных `<script>`) — вся разметка, стили и логика.
- `supabase-layer.js` (~26 КБ) — вход, выход, чтение/запись в базу.
- `config.js` — адрес проекта и ПУБЛИЧНЫЙ ключ.
- `supabase/` — серверная часть (сайт её не загружает).
- Данные: localStorage `pb24_release_v11` + таблицы Supabase.
- Таблицы: tasks, goals, projects, events, money, members, directions, profiles.
- Роли `profiles.role`: owner / member / viewer. Статус `profiles.access_status`: active / invited / revoked.

## Дизайн-система (не ломать)
- Все цвета, радиусы, тени и отступы — через CSS-переменные в `:root` в начале `<style>`. Хардкодить цвета в правилах нельзя.
- Шрифт: системный стек (`-apple-system, BlinkMacSystemFont, "SF Pro Display", "Segoe UI Variable", "Segoe UI", Inter, sans-serif`). Никаких внешних шрифтов — сайт должен работать без интернета.
- Сетка кратна 4/8 px. Радиусы 14–18. Заголовки с трекингом −0.02em.
- Переходы 140–220 мс, `cubic-bezier(.2,.7,.2,1)`. Обязательно `@media (prefers-reduced-motion: reduce)`.
- Мобильный вид — не «уменьшенный десктоп»: ≤900 px сайдбар превращается в нижний dock, ≤700 таблицы — в карточки.

## Иконки
- Набор из 137 SVG лежит в `icons.js` (`window.PB_ICONS`, только внутренняя разметка `viewBox="0 0 24 24"`).
- Логика выбора и показа — `icons-ui.js`: `pbIcon(name)`, `directionTileIcon(area)`, выбор через модалку `#pbIconPicker`.
- Храним имя иконки в колонках `icon` таблиц `directions`, `tasks`, `goals`, `projects`. Пустая строка = без иконки.
- Новые иконки добавляются только в `icons.js`; имена латиницей kebab-case.

## Банк и Яндекс.Диск
- Файлы физически лежат в Яндекс.Диске, в базе только карточки (`bank_files`: путь, имя, тип, размер, папка, автор, превью).
- **Client secret не попадает в браузер и репозиторий** — только в секреты Supabase (`YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`).
- **Токены Диска** — таблица `yandex_tokens`, RLS без политик, доступ только у `service_role` внутри Edge Function.
- Браузер получает только временные ссылки на загрузку/скачивание через Edge Function `yandex-disk`; прямых запросов к API Диска с токеном из браузера нет.
- Интерфейс — `bank-ui.js`; старую разметку банка не трогаем, она скрыта.

## Жёсткие правила
1. Ключ `service_role` никогда не попадает в браузерный код, `config.js`, коммит, README, скриншот или чат. Он живёт только в секретах Supabase.
2. Перед любым SQL, меняющим RLS, — резервная копия базы.
3. Порядок SQL строгий: 1) `team-access-migration.sql`, 2) `supabase/migrations/20261108_team_approval.sql`, 3) `supabase/migrations/20261108_delete_member.sql`, 4) `supabase/migrations/20261108_icons.sql`, 5) `supabase/migrations/20261108_bank_yandex.sql`.
4. `index.html` не переписываем целиком — только точечные правки. Строки там огромные, поэтому правим по уникальному фрагменту, а не по номеру строки.
5. Перед отдачей файла: `node --check supabase-layer.js` и проверка консоли браузера (F12 → Console, красных строк нет).
6. Не выдумывать имена функций, таблиц и полей. Не уверен — смотри файлы.
7. GitHub Pages кэширует: изменения видны через 1–10 минут, проверять Ctrl+Shift+R.

## Как работать
- Сначала план из 3–5 пунктов, потом код.
- Правка — покажи, что именно изменилось и почему (до/после).
- В конце — 2–3 шага проверки, которые владелец сделает сам.
- Нужен SQL — дай готовый блок целиком, для вставки в SQL Editor.
- Честно говори, что не проверено. Не обещай «всё работает», если не запускал.
- Один разговор — одна задача.

## Проверки перед отдачей
```
node --check supabase-layer.js
```
- Встроенные скрипты `index.html` проверяются только в браузере: F12 → Console.
- Диагностика базы: баннер `dbBanner` внизу экрана показывает текст ошибки и код.
